**Promise:** Decide whether, when and how to release your research code: which license, how others cite it, and how much maintenance you are promising.

**Trap:** Open source means making the repository public; in fact a public repository without a license gives others no right to reuse it, and the license and the maintenance stance decide whether anyone can.

**Assumes:** Nothing beyond having written research code.

## Outline

1. **Why release code at all**: verification of your results, reuse by others, and credit, weighed against the time it costs.
2. **Public is not open**: what a license grants, the difference between permissive and copyleft families, and the default when no license is present.
3. **Getting credit for software**: a citation file, an archived release with a persistent identifier, and software papers.
4. **Saying what you will maintain**: a project status in the README, issue triage you can sustain, and how to hand over or archive a project.
5. **What this means for you**: a release checklist for a single research repository.

## Key takeaways

- Code published without a license is, by default, not legally reusable by others. [verify]
- A citation file and an archived release make it more likely that reuse of the code is credited in papers. [verify]
- A README that states the maintenance level reduces support requests the author cannot meet.
- Most research software is maintained by one person, and stops being maintained when that person moves on. [verify]
